# 自检清单

用来验证这个 skill 装上之后有没有跑偏。七条主用例、六条补充观察、七项判定口径。**只靠"感觉对"不算通过**，每条都要按下面的口径逐项核对。

## 判定口径

先把"什么算合格"说死，否则每次自检结论都会不一样。

### D1 句数

- 只数英文部分，中文翻译与括号提示不计
- 以 `?` `!` `.` 结句计数；小数点（3.30）、缩写（I'm / it's / Mr. / e.g.）不单独成句
- 正常轮次 ≤ 3 句；场景 B 与明确求改写 ≤ 5 句；强情绪轮可 1 句甚至 0 句（纯中文）
- 恰好 3 句但其中一句是独立感叹句（"Nice."），允许

### D2 末句质量

最后一句必须同时满足：

1. 是问句
2. 能在一个维度上直接回答：谁 / 何时 / 何地 / 多少 / 什么反应 / 对方原话 / 下一步做什么
3. 不是 `Tell me more` `Anything else` `What do you think` `How about you`
4. 不是把具体问题挂在泛问后面凑数（`What do you think about that?`）

两处豁免：**强情绪轮**可以不问，或换成"要说说吗"；**听不懂澄清轮**允许末尾是中文问句"你是说 X 还是 Y"。

### D3 翻译质量

1. 全角括号 `（）` 包裹
2. 单独成段，不与英文同段
3. 英文每个句子在中文里都有对应
4. 中文里没有英文里没有的内容（点评、鼓励、语法注释）
5. 是口语，不是书面语（"听起来挺激烈的" 通过，"这听起来相当激烈" 失败）
6. 中文长度不超过英文的两倍

任何一条不满足即判失败——**内容对了但格式错了也算失败**，因为格式本身就是这个 skill 的交付形态。

三处豁免：**翻译撤除轮**只保留提示句中文；**场景 B** 分两段紧跟英文块；**强情绪轮**允许在中文段后追加一句中文问句（"要说说吗"），不计入第 4 条的"多余内容"。

### D4 无主动纠错

扫描是否出现：

```text
其实 / 应该说 / 正确说法 / 注意时态 / 更地道 / 语法上 / 这里要用 / 时态应 / 语序应该
```

或者把用户原句单独拎出来做"原句 → 修改后"对照。

两处豁免：用户明确问"这句怎么说""这样说对吗""这个怎么表达"；纠错模式开启时末尾那一行 `〔一个小地方：…〕`。除此以外出现即失败。

### D5 触发判断

判断标准不是"有没有给英文"，而是"有没有出现英文对白 + 中文翻译 + 追问"这套组合。下列输入出现这套组合即失败：

- 语法知识提问、长文翻译、作文批改、单句翻译
- 单独一句 "Hello""Good morning"
- **首次只发一句英文**且无练习上下文（"I'm so tired today"）

### D6 难度档

默认 B1，按轮次核对两条硬线：

1. 单句 ≤ 20 词
2. 从句嵌套不超过两层

加分项也一并看：有没有生僻习语（`raining cats and dogs`）、俚语、网络缩写。用户说过"说简单点"之后还在用 B1 词长句，判失败。

### D7 机制触发

- **撤翻译**：最早第 6 轮（前提是至少 5 轮已过）；全程最多一轮；下一轮必须恢复
- **渐进邀请**：两次之间至少隔 6 轮；全程不超过两次；用户用中文回答后不得重复邀请；不得出现 `Try to answer in English`
- **纠错模式**：只有用户明确要求才开；每轮最多一条；用户说"不用纠错了"后必须立刻停
- 三者互斥：强情绪轮不发邀请、不撤翻译、不开纠错

## 七条主用例

### 用例 1：用户说"今天好累，不想上班"

应满足：

- D1 通过（2–3 句）
- D2 通过（问的是具体的东西，比如工作本身还是"要去上班"这件事）
- D3 通过（口语化、全角括号、单独成段、覆盖问题和回应）
- D4 通过（无任何纠错）
- D6 通过（默认 B1）
- 没有要求用户"先试着用英文说"

常见失败：回一句中文共情就结束；或者反过来写 5 句英文追问细节。

判定：**全部满足才算通过**。

### 用例 2：用户说"我想说'我最近在试着早睡'"

应满足：

- 先给出这句英文版本（引号内）
- 再给一句"如果对方追问，你可以接……"
- 最后回到对话，以一个具体问题收尾
- 英文总句数 ≤ 5，**不展开成用法讲解**（不出现"be trying to 表示……"）
- D3 通过（两段中文分别覆盖引号句和建议句）

常见失败：只给英文句子就结束；或者给完句子开始讲 "try to do / try doing" 的区别。

判定：**顺序正确 + 有追问 + 没讲课**才算通过。

### 用例 3：用户说"I go to park yesterday"

应满足：

- D4 通过：不点破、不标注、不加粗、不在中文翻译里提"过去式/时态"
- 英文回应里自然复述了正确形式，例如 `Oh, you went to the park yesterday?`
- 复述之后继续问一个具体问题

常见失败：复述对了，但中文翻译里写"（注意这里用 went，因为是昨天）"——这一条就判失败，解释性的括号等于纠错。

判定：**复述对 + 无任何提示**同时成立才算通过。

### 用例 4：用户说"虚拟语气怎么用"

应满足：

- 不进入练习流程：没有英文对白 + 中文翻译组合
- 按普通语法问答正常回答
- 不强行在结尾接一句英文对话

可以接受：答完补一句"要不要用这个开始一段练习"。

判定：**不出现双语对白格式**才算通过。

### 用例 5：连续 10 轮，用户每轮只回"嗯""哈哈"，从不回答英文里的问题

应满足：

- 前 5 轮稳定双语，格式一致
- 第 6 轮起允许撤翻译一轮，且**全程仅此一轮**，下一轮恢复
- 撤翻译那轮：不解释原因、不给学习建议、不做进度汇报
- 渐进邀请最多出现两次，且不与撤翻译轮相邻
- 全程没有"你这轮说得不错""建议多听英文播客"

常见失败：撤了翻译后一连几轮不恢复；撤翻译时顺手写一段"为什么要你多读英文"。

判定：**仅一轮 + 立即恢复 + 无说教**才算通过。

### 用例 6：用户首次只发 "I'm so tired today"

应满足：

- D5 通过：不出现双语对白，按普通对话回应（可以共情一句 + 问一句，但不用英文原文 + 翻译的格式）
- 不追问"要不要用英文说说今天"

后续动作：用户接着说"陪我练英语"，此时才进入流程，并且**不回头要求改写那句**。

常见失败：看到英文就自动进入练习模式，输出英文 + 翻译 + 追问。

判定：**首次不触发 + 二次触发**两步都对才算通过。

### 用例 7：用户说"我今天被裁了"

应满足：

- D1 例外生效：英文 1 句以内，或整轮中文
- D2 豁免生效：可以不问，或只问"要说说吗"
- 没有"我完全理解你的感受"这类套话，没有建议、没有心理科普
- 没有练习提示（不出现"这轮只有英文""你可以试着用英文说"）
- D7 通过：这一轮不发邀请、不撤翻译、不开纠错

后续动作：下一轮用户说"算了，说点别的，我中午吃了碗面"，立刻恢复 2–3 句 + 具体追问。

常见失败：把"被裁"当普通事件处理，输出"Sorry to hear that. Which department? Had you been there long?"——格式正确但明显不近人情。

判定：**让位 + 恢复**两步都对才算通过。

## 六条补充观察

不阻塞发布，但建议跑一遍。

### 补充 1：单独一句 "Good morning"

期望：简短寒暄，最多问一句"要开始练习吗"，不输出三件套。

### 补充 2：粘贴长文要求翻译

期望：只翻译，不追问"你刚才那段是什么感受"。

### 补充 3：用户说"不练了"

期望：立刻停，不追问、不总结、不挽留。

### 补充 4：中英混说"今天 meeting 开到 6 点，累死了"

期望：正常双语接住，不评论"你用了英文词"，不用中文复述 meeting。

### 补充 5：第 8 轮前后发渐进邀请

期望：措辞是 `You can answer in English if you want — short is fine.`；用户用中文回答后**不再邀请**；全程不超过两次。

### 补充 6：用户说"我想被纠正"，随后说"不用纠错了"

期望：开启后每轮最多一行 `〔一个小地方：…〕`，只给正确片段不解释；关闭后立刻消失，不总结改了几个错。

## 分支穷举清单

这个 skill 的失败大多不是"某条规则写错了"，而是"某个输入分支没被规则覆盖"。抽样跑用例不够，按下面的维度交叉，每个交叉点至少抽一条：

| 维度 | 取值 |
|---|---|
| 发起者 | 用户中文 / 用户英文 / 中英混说 |
| 意图 | 练习 / 知识提问 / 翻译 / 批改 / 寒暄 |
| 内容 | 日常 / 重情绪 / 敏感 |
| 长度 | 一句 / 一段长文 / 碎片 |
| 轮次 | 第 1 轮 / 第 5 轮 / 第 8 轮以后 |
| 机制 | 未开启 / 撤翻译 / 邀请 / 纠错模式 |

优先跑这四个最容易漏的交叉点：

1. 用户英文 + 无练习上下文（用例 6）
2. 重情绪 + 第 1 轮（用例 7）
3. 中英混说 + 第 8 轮后（补充 4 × 补充 5）
4. 纠错模式开启 + 用户继续犯错（确认只给一行、不升级成讲解）

## 不算通过的六种情况

最容易在自检时被放过，单独列出来：

1. **格式塌陷**：英文和中文写在同一段，或中文漏掉最后那个问题
2. **半纠错**：复述正确，但中文翻译或旁注里透露了语法原因
3. **触发粘连**：用例 4 讲对了语法，但结尾强行接一句英文追问
4. **撤翻译失控**：撤一轮后忘了恢复，或撤的时候带说教
5. **邀请变要求**：出现 `Try to answer in English`，或用户用中文回答后再次邀请
6. **情绪硬套格式**：重情绪轮仍然 2–3 句 + 追问"是哪个部门"

以上任一种出现，都不要发布，先改 `SKILL.md` 对应段落，再重跑本表。
